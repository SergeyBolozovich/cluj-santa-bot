# Secret Santa Bot — Functional Specification v1.1

**Status:** Approved for Development  
**Platform:** Telegram Bot  
**Language:** Russian  
**Technology:** Python 3.12, python-telegram-bot  
**Database:** SQLite  
**Expected usage:** Seasonal, approximately 2 months per year  
**Development approach:** Improve the existing bot without unnecessary architectural complexity.

Документ определяет требования к будущей версии 1.1, а не перечень уже реализованных функций. Текущее поведение описано в [README](../README.md).

---

## 1. Overview

Secret Santa Bot позволяет организовывать обмен новогодними подарками непосредственно в Telegram-группах.

Организатор создаёт игру, устанавливает бюджет подарка и приглашает участников через сообщение в группе.

После завершения регистрации организатор вручную запускает жеребьёвку. Каждый участник получает личное сообщение с именем человека, которому должен подарить подарок.

Бот поддерживает несколько независимых игр, в том числе внутри одной Telegram-группы.

### Основные принципы

- Простота использования.
- Минимальное количество команд.
- Управление преимущественно через Telegram-кнопки.
- Сохранение данных после перезапуска.
- Конфиденциальность результатов жеребьёвки.
- Минимальные затраты на размещение и поддержку.

## 2. User Roles

### 2.1. Organizer

Пользователь Telegram, создавший игру.

**Возможности:**
- Создать новую игру.
- Указать название.
- Установить бюджет подарка.
- Просматривать список участников.
- Запустить жеребьёвку.
- Отменить игру до проведения жеребьёвки.
- Повторить неотправленные и неудачные уведомления без изменения назначений.

Создатель игры автоматически становится её организатором, независимо от статуса администратора Telegram-группы.

Организатор не получает доступ к чужим назначениям.

### 2.2. Participant

Пользователь Telegram, присоединившийся к игре.

**Возможности:**
- Присоединиться через кнопку в группе.
- Просматривать информацию об игре.
- Получить личное сообщение после жеребьёвки.
- Повторно посмотреть, кому необходимо подарить подарок.
- Участвовать одновременно в нескольких играх.

Отмена участия после регистрации не предусмотрена.

Организатор может также участвовать в игре, но должен зарегистрироваться как участник.

## 3. Functional Requirements

### SS-1. Event Creation

**Команды:** `/new` и `/new <название игры>`.

**Контекст:** Telegram-группа или супергруппа.

#### User Flow

1. Организатор отправляет `/new` в группе. `/new <название>` также принимается, но все поля всё равно вводятся в личном мастере.
2. Бот проверяет, что команда отправлена от собственного имени действующего участника группы (не анонимно и не ботом). Статус администратора не обязателен.
3. В группе появляется только приглашение «🎅 Создаём новую игру?\n\nЭльфы готовы к работе! Настроим всё в личном чате. 🧝» с URL-кнопкой «⚙️ Настроить игру».
4. Deep link `setup_<случайный идентификатор>` привязан к организатору и исходной группе, действителен 30 минут. Он не содержит токен бота или ID группы. После Start в Telegram личный мастер запрашивает название, затем бюджет в RON.
5. Организатор вручную вводит оба поля, используя прежние правила валидации. Ответы в группе не обрабатываются как ввод мастера; в личном чате обычный текст относится к текущей выбранной сессии.
6. Предварительный просмотр показывает фактически введённые значения и кнопки «🎁 Создать игру», «✏️ Изменить», «❌ Отмена». Изменение позволяет отдельно исправить название или бюджет до попытки публикации.
7. При подтверждении бот повторно проверяет личность организатора и его членство в исходной группе. При ошибке проверки публикация запрещена.
8. Бот сохраняет игру и состояние попытки публикации, затем отправляет в исходную группу самостоятельное объявление через `send_message`, без `reply_to_message_id` и `reply_parameters`. ID отправленного сообщения сохраняется для последующих редактирований. Только после этого организатор получает личное подтверждение успеха.

На каждом шаге доступны «❌ Отмена» и `/cancel` в личном чате; `/cancel` в исходной группе также отменяет собственный черновик для этой группы. Отмена до подтверждения не создаёт игру. Черновики привязаны к паре «Chat ID + Organizer ID», ссылка другого пользователя не даёт доступа к ним. При нескольких сессиях личный ввод относится к последней открытой через ссылку; можно переключиться ссылкой другой группы. Повторный `/new` до истечения срока возвращает ссылку той же сессии. Старые кнопки после изменения полей отклоняются по ID последнего сообщения мастера.

Незавершённое создание допустимо хранить только в памяти и сбрасывать после перезапуска. Старые кнопки такого черновика сообщают, что нужно начать заново. Подтверждение создаёт одну игру; повторное нажатие не создаёт копию.

#### SS-5.5 — Публикация и чистая группа

#### SS-5.6 — Возврат к группе и понятная регистрация

После успешного сохранения ID опубликованного объявления личное подтверждение сохраняет текст «🎉 Готово! Эльфы открыли регистрацию!\n\nИгра опубликована в группе. Теперь ждём участников! 🎁» и по возможности содержит URL-кнопку «↩️ Вернуться в группу».

Ссылка строится только из фактических данных исходной группы, полученных от Telegram, и сохранённого message_id: для публичной группы — `https://t.me/<фактический_username>/<message_id>`, для приватной супергруппы с корректным ID `-100…` — `https://t.me/c/<ID_без_-100>/<message_id>`. Приватная ссылка работает для пользователей с доступом к группе. Для обычной приватной группы такой формат не выдумывается: допустима только уже доступная invite-ссылка Telegram. Если прямой ссылки нет, но известен реальный публичный username, допустима ссылка на саму группу. Бот не создаёт invite-ссылки и не требует новых прав.

Если Telegram не возвращает данные группы, группа неподдерживаемого типа, ID некорректен или безопасная ссылка отсутствует, подтверждение показывается без кнопки. Это не отменяет уже успешную публикацию. Повторное подтверждение использует сохранённое объявление и не публикует новое. Формат самостоятельной отправки без reply-метаданных сохраняется; схема SQLite не меняется.

В групповой карточке прежние технические инструкции об активации заменяются одним блоком:

```text
📩 Секретная миссия ждёт тебя!

🧝 Чтобы эльфы смогли доставить тебе секретное задание, открой личный чат с ботом и активируй его.

🎁 Уже общался с ботом? Отлично! Просто жди жеребьёвки.
```

Ниже — существующий deep link «📩 Открыть бота». В тексте карточки нет указания нажимать START. Механизм Start в Telegram для новых пользователей, существующие активации, индикаторы ✅/⏳, сводка «📩 Связь с ботом: X/Y» и обновления всех участий остаются прежними.

До регистрации в карточке видно предупреждение: «🎅 Вступаешь в команду Санты всерьёз — после регистрации выйти из игры самостоятельно нельзя.». Оно заменяет «Регистрация необратима.», не меняя запрета выхода из игры. Назначения в группу не выводятся, активация не блокирует жеребьёвку.

- [ ] Успешная публикация даёт реальную прямую ссылку на публичное сообщение или сообщение приватной супергруппы.
- [ ] При отсутствии прямой ссылки используются только известные Telegram-ссылки группы; некорректные данные не порождают выдуманные URL и не ломают подтверждение.
- [ ] Точный блок активации и предупреждение видны до регистрации один раз, без технических указаний START в карточке.
- [ ] Счётчик, статусы активации, публикация без reply-заголовка и защита от повторов сохраняются.

#### Подробности SS-5.5

В группе остаются `/new`, приглашение в личный чат и итоговое объявление; название, бюджет, редактирование и подтверждение запрашиваются только лично. Удаление пользовательских сообщений и дополнительные права администратора не требуются. Итоговое объявление не привязано ответом к команде или сообщениям мастера.

Точные тексты личного мастера:

```text
🎄 Как назовём нашу игру?

Напиши название, которое увидят все участники.
```

```text
💰 Какой бюджет на подарок?

Введи сумму в RON, например: 70.
```

Подтверждение: «🎄 Проверим настройки игры!», затем «📝 Название: {введённое название}» и «💰 Бюджет: {введённая сумма} RON». После успешной публикации:

```text
🎉 Готово! Эльфы открыли регистрацию!

Игра опубликована в группе. Теперь ждём участников! 🎁
```

Повторное подтверждение опубликованной игры не отправляет новое объявление, включая после перезапуска. Дополнительная таблица `event_publications` хранит состояние отправки sending/failed/uncertain/published с уникальным event_id; существующие таблицы и данные не изменяются. Подтверждённая ошибка Telegram (запрет отправки, BadRequest, ограничение частоты) допускает повтор в живой сессии с тем же Event ID. После первой попытки значения заморожены; отмена после определённой ошибки сохраняет непубликовавшуюся игру как Cancelled.

При сетевом сбое/неопределённом результате, а также аварии после сохранения sending автоматическая повторная публикация запрещена: сообщение могло быть доставлено. Требуется ручная проверка группы и при необходимости восстановление ID в БД. Это ограничение Telegram: общей транзакции между SQLite и отправкой сообщения нет. Успех не сообщается до сохранения ID. При истечении сессии или перезапуске незавершённые поля вводятся заново; нельзя создавать новую попытку вслепую, если исход прежней отправки неизвестен.

#### Event Fields

| Field | Description |
|---|---|
| Event ID | Уникальный идентификатор |
| Chat ID | Telegram ID группы |
| Organizer ID | Telegram ID организатора |
| Title | Название игры |
| Budget | Сумма бюджета в банях, целое число |
| Currency | Только RON |
| Status | Статус игры |
| Message ID | ID сообщения в группе |
| Created At | Дата создания |

#### Business Rules

- Название обязательно: после удаления пробелов по краям — от 1 до 100 символов. Пользовательский текст экранируется при HTML-выводе.
- Бюджет обязателен: больше 0 и не больше 100 000 RON, максимум 2 знака после десятичного разделителя.
- Принимаются точка или запятая: `100`, `100.50`, `100,50`. Пробелы по краям удаляются; разделители тысяч, экспоненциальная запись, смешанные разделители и лишние десятичные знаки не принимаются. Некорректное значение не округляется автоматически.
- Значение хранится целым числом бань без вычислений через двоичный `float`: от 1 до 10 000 000 бань.
- Единственная поддерживаемая валюта — RON; выбора валюты нет.
- Можно создавать несколько игр в одной группе.
- Игры не зависят друг от друга.
- Только организатор управляет созданной им игрой.
- Создание игры не регистрирует организатора автоматически.

### SS-2. Participant Registration

**Trigger:** Кнопка «🎁 Присоединиться» в Telegram-группе.

#### User Flow

1. Пользователь нажимает «Присоединиться».
2. Бот проверяет статус игры.
3. Проверяет, не зарегистрирован ли пользователь.
4. Немедленно сохраняет участника в SQLite независимо от активации личного чата.
5. Обновляет список участников в сообщении группы.
6. Показывает подтверждение регистрации. Если личный чат ещё не активирован, публикует адресованное этому участнику сообщение с кнопкой «📩 Открыть бота» и Telegram deep link.

#### Business Rules

- Регистрация доступна только в статусе Registration Open, включая время ожидания подтверждения жеребьёвки.
- Один Telegram-пользователь может участвовать в конкретной игре только один раз.
- Повторное нажатие не создаёт дубликат и показывает callback-уведомление «✅ Ты уже участвуешь в этой игре!» без новой регистрации или нового сообщения активации.
- Предварительно отправлять `/start` для регистрации не нужно. Регистрация в игре и активация личного чата — независимые состояния.
- Пока регистрация открыта, кнопка «🎁 Присоединиться» остаётся для всех. Telegram не позволяет отключить inline-кнопку общего группового сообщения только для одного пользователя.
- После закрытия регистрации, отмены или завершения жеребьёвки кнопка регистрации удаляется для всех; кнопка управления организатора сохраняется там, где применима. Старые нажатия проверяют актуальный статус игры.
- Пользователь может участвовать в нескольких играх.
- Участники идентифицируются по Telegram User ID.
- Список участников виден всем членам группы.
- Регистрация необратима: ни участник, ни организатор не могут удалить участника из игры. При необходимости организатор может отменить всю игру до жеребьёвки.

#### Group Message Example

🎅 **Тайный Санта 2026**

🎁 Бюджет: 100 RON  
👥 Участников: 4  
🟢 Регистрация открыта

**Участники:**
1. Алексей
2. Мария
3. Андрей
4. Сергей

**Buttons:**
- 🎁 Присоединиться
- 🎲 Провести жеребьёвку
- ⚙️ Управление

Кнопки жеребьёвки и управления видны в групповом сообщении, но соответствующие действия разрешены только организатору. Управление доступно создателю даже без регистрации участником: до жеребьёвки — отмена игры с подтверждением, после — состояние рассылки и «Повторить неудачные уведомления». Чужие назначения не показываются. Все действия привязаны к Event ID, права и статус проверяются при каждом нажатии.

### SS-3. Private Bot Activation

Telegram не позволяет боту первым отправлять личные сообщения пользователям, которые ещё не начали с ним диалог.

Для получения личных сообщений и просмотра сохранённого результата участник активирует бота в личном чате. Это можно сделать после жеребьёвки: активация не является условием её запуска.

#### User Flow

1. Пользователь регистрируется через кнопку в группе.
2. Если личный чат не активирован, бот показывает адресованное участнику сообщение в группе с кнопкой «📩 Открыть бота». Сообщение и URL-кнопка видны группе: Telegram не поддерживает отдельную персональную inline-клавиатуру в общем сообщении.
3. Кнопка открывает личный чат через `https://t.me/<bot_username>?start=activate_<event_id>`. Пользователь нажимает Start («Запустить») в Telegram; вручную вводить `/start` не требуется.
4. Обработчик `/start activate_<event_id>` сохраняет активацию фактического Telegram-пользователя в SQLite и подтверждает её. Открытие ссылки без нажатия Start ничего не активирует.
5. Уже активированному пользователю повторная активация не требуется. Обычный `/start` также остаётся доступным и открывает личное меню.

#### Business Rules

- Регистрация в группе не требует предварительного запуска личного чата.
- Активация личного чата сохраняется в SQLite и не теряется при перезапуске.
- Активация относится к Telegram User ID, а не к одной игре, и действует для всех его участий. Повторная активация безопасна и не создаёт дубликатов.
- Deep link содержит контекст игры, но не подтверждает личность и не регистрирует пользователя. Сохраняется только Telegram User ID отправителя `/start`; нажатие ссылки другим членом группы не активирует исходного участника.
- Активация по ссылке не меняет участников, статус игры, сохранённые назначения и состояние уведомлений, в том числе для завершённой или отменённой игры.
- Активация и доступность личного чата не ограничивают показ подтверждения и запуск жеребьёвки. Достаточно минимум 2 зарегистрированных участников и подтверждения организатора открытой игры.
- Предварительных пробных отправок нет. Сначала атомарно сохраняются все пары и завершённый статус, затем выполняется попытка личного уведомления каждого участника.
- Неактивированный или заблокированный чат и ошибки Telegram не отменяют жеребьёвку. Неудачная отправка получает статус failed, назначение сохраняется, отправка другим участникам продолжается.
- После Start участник может открыть «Мои игры» → «Кому я дарю?» и прочитать прежнее назначение без новой жеребьёвки. Организатор также может повторить неудачные уведомления.
- Успешный `/start` не гарантирует последующую доставку: пользователь может заблокировать бота позже, возможны сетевые ошибки и сбои Telegram. Организатор видит только счётчики успешных, неудачных и ожидающих отправки уведомлений, без назначений.

### SS-4. Draw Management

**Trigger:** Кнопка «🎲 Провести жеребьёвку».

#### Preconditions

- Игра находится в статусе Registration Open.
- Зарегистрировано минимум 2 участника.
- Активация личных чатов не требуется для жеребьёвки и не проверяется как предусловие.
- Инициатор является организатором игры.

#### User Flow

1. Организатор нажимает «Провести жеребьёвку».
2. Бот проверяет организатора, открытый статус и минимум 2 зарегистрированных участников независимо от активации личных чатов.
3. Показывает название, бюджет, текущий состав и количество участников, кнопки «Подтвердить жеребьёвку» и «Назад».
4. Организатор подтверждает запуск. Бот повторно проверяет его права, статус Registration Open, минимум 2 участника и соответствие состава показанному подтверждению. При изменении состава показывает новое подтверждение, не проводя жеребьёвку по устаревшему списку.
5. В короткой транзакции SQLite бот повторно проверяет статус и состав, генерирует назначения и сохраняет все пары вместе со статусом Draw Completed атомарно. Начальное состояние каждого уведомления — pending. До успешного commit сообщений участникам нет.
6. Только после успешной фиксации транзакции бот отправляет личные уведомления, записывая результат каждой попытки отдельно.
7. Обновляет сообщение в группе: жеребьёвка завершена, регистрация закрыта, список и число участников сохранены. Состояние доставки не меняет завершённый статус игры.

Повторные и устаревшие подтверждения не запускают новую жеребьёвку. Подтверждение связано с конкретной игрой и составом участников. Сетевые запросы не выполняются внутри транзакции SQLite; параллельная регистрация или отмена разрешается проверками состояния в транзакции.

#### Assignment Rules

- Каждый участник дарит один подарок.
- Каждый участник получает один подарок.
- Никто не может получить самого себя.
- Минимальное количество участников — 2.
- В игре с двумя участниками они получают друг друга.
- Исключения между участниками отсутствуют.
- Повторная жеребьёвка после завершения запрещена.
- Назначения сохраняются и не меняются после перезапуска бота.

#### Error Handling

- Если участник не активировал или заблокировал бота, жеребьёвка всё равно сохраняется. Ошибка личной отправки не изменяет его назначение и не мешает уведомлениям остальных.
- Если отправка отдельного сообщения не удалась, результат жеребьёвки сохраняется.
- Неуспешное уведомление можно отправить повторно.
- Повторная отправка не изменяет назначение.
- При ошибке транзакции не сохраняется ни часть пар, ни завершённый статус; уведомления не отправляются. После сбоя до фиксации игра остаётся открытой, требуется новое подтверждение.
- После фиксации пар сбой или перезапуск не запускает новое распределение. Неотправленные уведомления доступны для повторной отправки.
- Организатор запускает «Повторить неудачные уведомления» через управление игрой; обрабатываются записи pending и failed, отправляется только ранее сохранённое назначение.
- Если сообщение доставлено, но процесс завершился до записи успеха, после перезапуска допустимо повторное уведомление с тем же назначением. Гарантия доставки ровно одного сообщения не предоставляется.

### SS-5. Assignment Notification

После сохранения жеребьёвки бот пытается отправить каждому участнику личное сообщение. Доставку Telegram гарантировать нельзя; назначение остаётся доступным в личном меню независимо от результата уведомления.

### SS-8. Event Cancellation

Организатор может отменить игру до жеребьёвки.

#### Flow

1. Организатор нажимает «⚙️ Управление» в групповом сообщении нужной игры.
2. Выбирает «Отменить игру».
3. Бот запрашивает подтверждение.
4. После подтверждения статус меняется на Cancelled.
5. Регистрация и жеребьёвка блокируются.

При подтверждении повторно проверяются организатор и статус Registration Open. Повторная отмена безопасна; если жеребьёвка уже сохранена, отмена отклоняется. Карточка группы обновляется, а старые кнопки не обходят проверку статуса.

Отменённая игра остаётся в базе для истории.

Отмена завершённой жеребьёвки не предусмотрена.

## 4. Event Statuses

| Status | Description |
|---|---|
| Registration Open | Игра создана, регистрация доступна |
| Draw In Progress | Только внутренний этап короткой транзакции; не сохраняется как устойчивое состояние |
| Draw Completed | Назначения сохранены, результаты доступны |
| Cancelled | Игра отменена |

Состояние отправки уведомлений хранится отдельно от статуса игры.

Допустимые устойчивые переходы: Registration Open → Draw Completed либо Registration Open → Cancelled. Все назначения и Draw Completed фиксируются одной транзакцией; при откате сохраняется Registration Open. Завершение означает сохранённые пары, а не доставку всех сообщений. Пользователю статусы отображаются только по-русски.

## 5. Data Persistence

### SS-9. SQLite Storage

Для хранения данных используется SQLite.

SQLite выбрана из-за:
- Простоты.
- Отсутствия отдельного сервера базы данных.
- Небольшого количества пользователей.
- Сезонного использования бота.
- Возможности сохранить все данные в одном файле.

#### Data Entities

**Events**
- id
- chat_id
- organizer_id
- title
- budget (целое количество бань)
- currency
- status
- message_id
- created_at

**Participants**
- id
- event_id
- telegram_user_id
- display_name
- joined_at

**Assignments**
- id
- event_id
- giver_user_id
- receiver_user_id
- notification_status

**Users**
- telegram_user_id
- private_started_at

Для уведомлений используются состояния pending (ещё не подтверждена отправка), sent (Telegram подтвердил отправку), failed (попытка завершилась ошибкой). Они не меняют статус игры. Подтверждение отправки не означает прочтение сообщения.

#### Requirements

- Данные сохраняются после перезапуска.
- При обновлении приложения данные не удаляются.
- Повторная регистрация не создаёт дубликаты.
- Все назначения и статус Draw Completed сохраняются атомарно до отправки уведомлений.
- Уникальность участника обеспечивается парой (event_id, telegram_user_id), дарителя — (event_id, giver_user_id), получателя — (event_id, receiver_user_id). Самоназначения запрещены; ссылки на события и участников проверяются средствами SQLite и приложения.
- Повторный запуск бота не запускает новую жеребьёвку.
- SQLite-файл хранится на постоянном диске хостинга.
- Предусмотрена возможность резервного копирования базы.

## 7. Technical Requirements

### Architecture

Сохраняем существующий Python-проект.

Не требуется создавать сложную многослойную архитектуру.

Допускается минимальное разделение:
- `bot.py` — запуск приложения.
- `handlers.py` — Telegram-команды и кнопки.
- `storage.py` — SQLite.
- `draw.py` — алгоритм жеребьёвки.
- `config.py` — конфигурация.

Фактическую структуру определяем при реализации с учётом существующего кода.

Для сезонной нагрузки достаточно одного polling-процесса и стандартного `sqlite3`. Отдельный сервер БД, очередь задач, веб-сервис и обязательное разделение на все перечисленные модули не требуются. Существующие работающие сценарии регистрации и жеребьёвки сохраняются с добавлением проверок и постоянного хранения.

### Configuration

- Telegram Bot Token хранится в переменных окружения.
- `.env` исключён из Git.
- Добавляется `.env.example` без секретов.
- Имя Telegram-бота не должно быть жёстко прописано в коде.
- Существующий long polling сохраняется.

### Deployment

- Бот должен работать непрерывно в период проведения игр.
- Предпочтителен недорогой хостинг.
- SQLite должна храниться на постоянном диске.
- Деплой не должен удалять базу данных.
- Одновременно работает только один polling-процесс с данным токеном.
- После новогоднего периода бот можно остановить.

Конкретная платформа хостинга будет выбрана отдельно.

## 8. Non-Functional Requirements

### Reliability
- Сохранение данных при перезапуске.
- Корректная обработка ошибок Telegram API.
- Отсутствие повторных назначений после сбоев.

### Usability
- Все сообщения на русском языке.
- Простое управление кнопками.
- Минимальное количество команд.
- Понятные сообщения об ошибках.

## 10. Acceptance Criteria

### Уточнения SS-5: праздничные сообщения и навигация

#### SS-5.4 — Статус активации участников

В существующей групповой карточке перед именем каждого зарегистрированного участника показывается `✅`, если в таблице SS-4 `users` есть запись его Telegram User ID, либо `⏳`, если записи нет. Состояние вычисляется при чтении, без нового столбца или дублирования данных. Оно видно всей группе.

Карточка содержит сводку `📩 Связь с ботом: {activated_count}/{participant_count}` и легенду:

```text
✅ — личный чат активирован
⏳ — ожидает активации
```

После регистрации обновляются список и сводка. После личного Start обновляются существующие карточки всех игр пользователя, включая завершённые и отменённые, в той же или других группах. Это полный список участий, а не первая страница «Моих игр». Организатор без участия не учитывается. Повторный Start безопасен и повторяет попытку обновления карточек, включая после перезапуска.

Отдельных групповых сообщений об активации нет. Удалённая или недоступная для редактирования карточка и ошибки Telegram не отменяют регистрацию, активацию или жеребьёвку и не мешают обновлению остальных карточек. При следующем Start/действии обновление можно повторить; автоматическая очередь повторных редактирований не требуется.

`✅` означает только ранее выполненный Start, а не текущую доставляемость личных сообщений. Состояния уведомлений pending/sent/failed и их повторы не меняются; жеребьёвка доступна от 2 участников независимо от активации. Сводка и индикаторы не содержат назначений и сохраняются в карточке после закрытия регистрации.

- [ ] Смешанный список, пустая игра и суммарное число активаций отображаются корректно.
- [ ] Регистрация и Start обновляют ту же карточку; Start обновляет все участия, включая больше одной страницы и закрытые игры.
- [ ] Перезапуск сохраняет индикаторы через существующие записи SS-4.
- [ ] Ошибка редактирования одной карточки не мешает другим и не портит сохранённые состояния или результаты жеребьёвки.

#### Шаблоны сообщений SS-5

Вступление групповой карточки неизменно при редактировании участников и статуса:

```text
🎄 Санта объявляет сбор!

Эльфы уже готовят списки, подарки сами себя не купят, а Новый год ждать не будет! 🎁

Присоединяйся к Тайному Санте - пусть начнётся праздничная интрига!
```

Название, бюджет, список и число участников, статус и разрешённые кнопки сохраняются. Новые объявления вместо редактирования карточки не создаются.

Успешная регистрация: callback «🎉 Ты в деле! Эльфы внесли тебя в список Санты! 🧝». Для неактивированного участника переиспользуется существующее адресное сообщение, без дополнительных постов и без кнопок в toast:

```text
🎉 Ты в деле!
🧝 Эльфы внесли тебя в секретный список Санты. Отступать поздно - Санта всё видел! 👀
🎁 Теперь жди жеребьёвки и своей секретной миссии!
```

Кнопка этого сообщения — «📩 Открыть бота», прежний deep link и Start сохраняются. Уже активированным адресное сообщение не отправляется.

После сохранения пар существующая карточка дополняется одним блоком завершения, без отдельного объявления. Повторы рассылки и перезапуск не создают новые праздничные посты:

```text
🎲 Жеребьёвка завершена!

🧝 Эльфы распределили секретные миссии!

🎁 Проверь личный чат с ботом - там тебя ждёт имя счастливчика.

🤫 И помни: настоящий Тайный Санта умеет хранить секреты!
```

Счётчики sent/failed/pending показываются только организатору в callback-окне. Если callback устарел после долгой рассылки, актуальные счётчики доступны через «Управление». В группе нет статистики и назначений.

Отдельная кнопка главного меню «🎯 Кому я дарю?» читает сохранённые назначения текущего пользователя: одно — показывает сразу, несколько — предлагает список игр со страницами по 5 записей. Нет сохранённых назначений, но есть участия — «⏳ Санта ещё не провёл жеребьёвку. Немного терпения!». Нет участий — предложение присоединиться кнопкой в группе. Старое завершённое событие без пары при прямом просмотре сопровождается пояснением о недостающих данных.

«Мои игры» сохраняет все участия и страницы; завершённая карточка предлагает собственное назначение, открытая — ожидание. Кнопки «⬅️ Назад» и «🏠 Главное меню» возвращают в исходный список/страницу или меню. Callback-навигация редактирует существующее личное сообщение. Старые callback `games`, `game`, `recipient`, `private_menu`, `private_help` сохраняют работоспособность.

Точные короткие ответы: закрытая регистрация — «🔒 Регистрация закрыта. Санта уже составляет списки!»; мало участников — «🎅 Для жеребьёвки нужны хотя бы 2 участника.»; ожидание — «⏳ Санта ещё не провёл жеребьёвку. Немного терпения!»; отменённая игра — «🚫 Эта игра отменена организатором.».

Алгоритм, атомарность и защита от конкурентных жеребьёвок не меняются. SS-5.5 добавляет только таблицу состояния публикаций; прежние таблицы сохраняются. Минимум 2 участника достаточен независимо от активации личного чата. Все назначения остаются приватными.

- [ ] Точные праздничные шаблоны и динамические значения проверены тестами.
- [ ] Одно групповое объявление сохраняется при обновлениях, завершении, повторах и перезапуске.
- [ ] Главное меню содержит три независимых работающих действия; ветка получателя корректна для 0, 1 и нескольких сохранённых назначений.
- [ ] Навигация редактирует личное сообщение и сохраняет исходную страницу; чужие пары недоступны.

- [ ] Организатор может создать игру с названием и бюджетом.
- [ ] Бюджет отображается в RON.
- [ ] Участники регистрируются через кнопку в группе.
- [ ] Список участников обновляется.
- [ ] Повторная регистрация не создаёт дубликат.
- [ ] Несколько игр работают независимо.
- [ ] Организатор может вручную запустить жеребьёвку.
- [ ] Минимум участников — 2.
- [ ] Никто не получает самого себя.
- [ ] Каждый участник получает ровно одно назначение.
- [ ] Бот пытается отправить результаты в личные сообщения и сохраняет состояние каждой отправки; гарантированная доставка не требуется.
- [ ] Участник может посмотреть своё назначение повторно.
- [ ] Организатор не видит чужие назначения.
- [ ] Бот сохраняет данные после перезапуска.
- [ ] Повторный запуск не изменяет результаты.
- [ ] Ошибки отправки сообщений не приводят к повторной жеребьёвке.
- [ ] Организатор может отменить игру до жеребьёвки.
- [ ] Бот можно развернуть на хостинге с постоянным хранением SQLite.
- [ ] `/new` и `/new <название игры>` показывают в группе приглашение в личный мастер; промежуточные вопросы и ввод не публикуются в группе.
- [ ] Создание можно прервать кнопкой «Отмена» или `/cancel`; опубликованные игры не затрагиваются.
- [ ] Ответы разных организаторов не смешиваются; повторное подтверждение создания не создаёт дубликат.
- [ ] Setup-ссылка привязана к организатору и группе, истекает через 30 минут и не позволяет другому пользователю управлять сессией.
- [ ] Название и бюджет вводятся вручную в личном чате и могут быть изменены по отдельности до публикации; значения не берутся из примеров.
- [ ] Членство организатора проверяется при `/new`, открытии ссылки и перед публикацией; анонимные команды и боты отклоняются.
- [ ] Самостоятельное объявление отправляется без reply-метаданных в исходную группу; сохранённый message_id используется при регистрации и Start.
- [ ] Ошибка публикации не выдаётся за успех; повтор подтверждения не создаёт вторую игру или объявление, неопределённый исход отправки блокирует автоматический повтор.
- [ ] После перезапуска незавершённый черновик может исчезнуть; его старые кнопки предлагают начать заново.
- [ ] Название длиной 1 и 100 символов после удаления крайних пробелов принимается; пустое и длиннее 100 отклоняется. HTML-символы выводятся безопасно.
- [ ] Принимаются бюджеты `0.01`, `0,01`, `100`, `100.50`, `100,50`, `100000` и `100000,00` RON.
- [ ] Ноль, отрицательные суммы, суммы больше 100 000 RON, более 2 десятичных знаков и некорректные форматы отклоняются без округления.
- [ ] Бюджет хранится целым количеством бань; RON — единственная валюта, весь пользовательский интерфейс русский.
- [ ] «⚙️ Управление» доступно организатору через карточку группы, даже если он не участник; чужие действия отклоняются.
- [ ] Ни участник, ни организатор не могут отменить регистрацию отдельного участника.
- [ ] До жеребьёвки обязательно подтверждение; при подтверждении повторно проверяются статус, организатор и состав. Изменившийся состав требует нового подтверждения.
- [ ] При 0 или 1 участнике жеребьёвка запрещена; при 2 участниках они получают друг друга, каждый также является получателем ровно одного подарка.
- [ ] Жеребьёвка доступна с минимум 2 участниками даже без активации всех личных чатов. Все пары сохраняются до первой попытки сообщения; пробных отправок до commit нет.
- [ ] Все пары и Draw Completed фиксируются одной транзакцией до первого уведомления. Ошибка транзакции не оставляет частичных результатов.
- [ ] Повторные нажатия и старые кнопки не меняют завершённую или отменённую игру и не воздействуют на другую игру в том же чате.
- [ ] Сбой после фиксации результатов или посреди рассылки не меняет пары; результаты доступны через «Мои игры» → «Кому я дарю?» после перезапуска.
- [ ] Ошибка одного уведомления не мешает попыткам отправки остальных; организатор может повторить pending/failed без просмотра чужих назначений.
- [ ] Повтор уведомления после сбоя содержит то же назначение; возможный дубликат допустим и не считается повторной жеребьёвкой.
- [ ] Пользователь не может получить чужую пару подменой Event ID или данных кнопки.
- [ ] Отмена повторно проверяет открытый статус; завершённую игру отменить нельзя. Отменённая игра остаётся в истории без активных действий.
- [ ] Обновление и перезапуск сохраняют SQLite на постоянном диске; проверено восстановление резервной копии, работает один polling-процесс.
- [ ] Первое нажатие «🎁 Присоединиться» сохраняет участие без предварительного `/start` и обновляет список и число участников.
- [ ] Повторное нажатие показывает точно «✅ Ты уже участвуешь в этой игре!», не создаёт запись или повторное адресное сообщение активации.
- [ ] Неактивированному участнику предоставлена кнопка «📩 Открыть бота» с Telegram deep link; уже активированному повторная активация не предлагается.
- [ ] Открытие ссылки само по себе не активирует чат. Start по deep link сохраняет активацию фактического пользователя, не регистрирует его автоматически и не меняет чужую активацию.
- [ ] Повторная активация и перезапуск сохраняют одну запись пользователя; активация действует во всех его играх.
- [ ] Кнопка регистрации остаётся в открытой игре после регистрации участника и исчезает для всех после отмены или завершения жеребьёвки.
- [ ] Неактивированный участник после Start видит своё сохранённое назначение через «Мои игры» → «Кому я дарю?», в том числе после перезапуска; новая жеребьёвка не выполняется.
- [ ] При смешанной доступности чатов доступные участники получают сообщения, неудачные отправки учитываются отдельно; организатор видит счётчики без раскрытия пар.
