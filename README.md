# CLUJ-SANTA-BOT

Telegram-бот для организации «Тайного Санты» в группах: собирает участников, случайно распределяет получателей подарков и отправляет каждому участнику результат в личные сообщения.

Этот документ описывает текущую реализацию из `bot.py` и отдельно — планы версии **1.1**. Запланированные возможности ещё не реализованы, если явно не указано обратное.

Согласованные требования будущей версии: [функциональная спецификация v1.1](docs/functional-specification.md). Бот рассчитан на сезонное использование около двух месяцев в году; архитектура остаётся минимальной.

## Технологии

- Python **3.12.9** — версия, указанная в `runtime.txt`.
- `python-telegram-bot==21.6` — единственная прямая зависимость в `requirements.txt`.
- Асинхронные обработчики Telegram Bot API, inline-кнопки и HTML-разметка сообщений.
- Получение обновлений через polling (`Application.run_polling()`).
- Стандартные модули `os`, `random`, `typing`; состояние хранится в памяти процесса в словарях и множествах.

## Текущие возможности

- Создание игры в группе или супергруппе с произвольным названием.
- Одна текущая игра на каждый групповой чат; разные группы имеют отдельные записи в памяти.
- Регистрация через кнопку «✅ Присоединиться» в сообщении группы и обновление списка участников.
- Защита от повторного добавления одного пользователя в список.
- Учёт пользователей, отправивших `/start` в личном чате с ботом в течение текущего запуска процесса.
- Ручной запуск жеребьёвки создателем игры: минимум два участника, все должны предварительно отправить `/start` боту в личном чате.
- Случайное распределение: каждый дарит одному участнику и получает подарок от одного участника; назначение самому себе исключено. Алгоритм делает до 1000 попыток перемешивания.
- Личная отправка имени получателя и его `@username` либо ссылки на профиль.
- После успешной рассылки — отметка о завершении жеребьёвки и уведомление группы.

## Команды и сценарий участия

| Команда или кнопка | Где доступна | Действие |
| --- | --- | --- |
| `/start` | Личный чат | Запоминает готовность пользователя получать результаты и показывает приветствие. В группе обработчик ничего не делает. |
| `/new [название]` | Группа или супергруппа | Создаёт игру. Без названия используется `Secret Santa 🎄`. В личном чате команда ничего не делает. |
| «✅ Присоединиться» | Сообщение игры в группе | Добавляет пользователя в текущую игру, пока жеребьёвка не завершена. |
| «🎲 Жеребьёвка» | Сообщение игры в группе | Запускает распределение по нажатию создателя игры. |
| «🎲 Жеребьёвка завершена» | Сообщение завершённой игры | Подтверждает нажатие без дополнительных действий. |

1. Добавьте бота в группу и обеспечьте ему возможность отправлять и редактировать собственные сообщения.
2. Организатор отправляет, например, `/new Тайный Санта Клуж`.
3. Каждый участник открывает личный чат с ботом, нажимает `/start`, затем возвращается в группу и нажимает «✅ Присоединиться».
4. Организатор при желании тоже присоединяется кнопкой: создание игры не добавляет его автоматически.
5. Когда все готовы, организатор нажимает «🎲 Жеребьёвка».
6. Участники получают личные сообщения с получателями подарков.

Регистрация технически возможна до личного `/start`, но без него бот не разрешит жеребьёвку. Создателем считается пользователь, вызвавший `/new`; проверка статуса администратора группы отсутствует.

## Требования и локальная настройка

Потребуются Python 3.12.9, `pip`, доступ к Telegram API по сети и токен Telegram-бота, полученный через BotFather. Ниже приведены инструкции для самостоятельного запуска.

Откройте терминал в корне репозитория. Для Windows PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Для Linux/macOS с установленным Python 3.12:

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

Зависимости библиотеки установит `pip`. SQLite и дополнительные пакеты для загрузки `.env` сейчас не используются.

## Настройка BOT_TOKEN

Бот читает токен из переменной окружения `BOT_TOKEN` при загрузке `bot.py`. Установите её **до запуска** в той же сессии терминала.

Windows PowerShell:

```powershell
$env:BOT_TOKEN = '<ТОКЕН_ВАШЕГО_БОТА>'
```

Linux/macOS:

```bash
export BOT_TOKEN='<ТОКЕН_ВАШЕГО_БОТА>'
```

Значение в угловых скобках — заполнитель, а не действующий токен. Не публикуйте токен в Git, документации, сообщениях или логах. При размещении используйте переменные окружения либо хранилище секретов платформы.

**Файл `.env` автоматически не загружается.** Его наличие в `.gitignore` не включает такую поддержку: текущий код использует только `os.getenv()`.

В коде также задан `BOT_USERNAME = "Cluj_Secret_Santa_bot"`. Он используется в ссылке на бота в групповом сообщении и не настраивается через окружение. Если токен принадлежит другому боту, ссылка останется прежней; это ограничение текущей конфигурации.

## Локальный запуск

После установки зависимостей и задания `BOT_TOKEN` выполните:

Windows PowerShell:

```powershell
.\.venv\Scripts\python.exe bot.py
```

Linux/macOS:

```bash
.venv/bin/python bot.py
```

Процесс должен оставаться запущенным для обработки сообщений. Для остановки нажмите `Ctrl+C`. Если `BOT_TOKEN` отсутствует или пуст, запуск завершится с `RuntimeError: BOT_TOKEN не найден`.

## Текущие технические ограничения

- **Нет постоянного хранения.** Перезапуск удаляет игры, участников, признак завершения и сведения о личных `/start`. После перезапуска участникам потребуется снова отправить `/start`; старые сообщения группы не восстанавливают игру.
- **Одна запись на чат.** Повторный `/new` заменяет текущую игру, включая организатора и участников. Создать её может любой пользователь группы.
- **Старые кнопки не привязаны к отдельной игре.** Обработчики выбирают игру только по ID чата и не сверяют ID сообщения; кнопки прежних сообщений могут воздействовать на новую игру в том же чате.
- **Результаты не сохраняются.** Пары существуют только во время рассылки. Нет меню «Мои игры», истории и повторного просмотра назначения через команду бота. Уже доставленное сообщение остаётся в личном чате Telegram.
- Нет бюджета подарка, выхода из игры, удаления участников, отмены игры или расписания жеребьёвки.
- Рассылка выполняется последовательно без обработки ошибок доставки и повторных попыток на уровне приложения. Блокировка бота или ошибка API может прервать рассылку после части сообщений; признак завершения устанавливается лишь после отправки всех назначений.
- Обработчик жеребьёвки не проверяет `drawn` повторно. Завершение отражается заменой кнопок, но отдельной защиты от повторной обработки старого нажатия нет.
- Имена и название вставляются в HTML без экранирования: специальные символы могут нарушить разметку или отправку сообщения.
- Ошибки получения имён для списка участников подавляются; отдельные участники могут отсутствовать в отображаемом списке, оставаясь зарегистрированными.
- После завершения карточка игры отображается с пустым списком участников, хотя их ID остаются в памяти до замены игры или перезапуска.
- Нет настроенного прикладного логирования, мониторинга и автоматизированных тестов в рассмотренной структуре.

### Согласованные сценарии v1.1 — ещё не реализованы

- `/new` запускает ввод названия и бюджета; `/new <название игры>` использует переданное название и переходит к бюджету. После предварительного просмотра требуется подтверждение создания.
- Название после удаления пробелов по краям: 1–100 символов. Бюджет: положительная сумма до 100 000 RON включительно, максимум 2 десятичных знака. Принимаются точка и запятая (`100.50`, `100,50`); неверные значения не округляются. В SQLite сумма хранится целым количеством бань. RON — единственная валюта.
- На любом шаге создания доступны «Отмена» и `/cancel`. Они отменяют только собственный черновик в текущей группе. Незавершённое создание можно сбросить после перезапуска; опубликованные игры сохраняются.
- В групповую карточку добавляется «⚙️ Управление». Только организатор может отменить открытую игру с подтверждением или повторить неудачные уведомления завершённой игры. Для управления ему не обязательно регистрироваться участником; чужие назначения не показываются.
- Регистрация остаётся необратимой: удалить отдельного участника нельзя. Каждая игра имеет собственный ID, список участников и бюджет; несколько игр в одной группе не заменяют друг друга.
- Для жеребьёвки нужны минимум 2 участника и отдельное подтверждение организатора. При подтверждении повторно проверяются права, открытый статус и состав; изменение состава требует нового подтверждения. При двух участниках они получают друг друга.
- До сохранения пар проверяется активация личного чата и выполняется пробная отправка без назначения. Ошибка проверки останавливает запуск. Успешная проверка не гарантирует последующую доставку Telegram.
- Все назначения и завершённый статус сохраняются **атомарно до рассылки**. Ошибка транзакции не оставляет частичных пар; повторное нажатие или перезапуск не меняют сохранённые назначения.
- Состояние уведомлений хранится отдельно. Организатор может повторить неотправленные и неудачные уведомления, используя прежние пары. После сбоя допустим дубликат сообщения с тем же назначением; доставка Telegram не гарантируется.
- Личное меню сохраняет путь «Мои игры» → карточка игры → «Кому я дарю?». Просмотр собственной сохранённой пары не зависит от успешности исходного уведомления. Добавляются `/mygames` и `/help`; весь интерфейс — только на русском.
- Для сезонной нагрузки достаточно одного polling-процесса и SQLite через стандартный `sqlite3`, без отдельного сервера БД и очереди задач. Имя бота для ссылок перестаёт быть фиксированным; планируется `.env.example` без секретов.

Критерии приёмки, включая валидацию, старые кнопки, сбои транзакции и рассылки, повторные уведомления и восстановление данных, перечислены в [спецификации](docs/functional-specification.md#10-acceptance-criteria).

## Развёртывание

- Нужен постоянно работающий процесс с Python и установленными зависимостями; команда запуска — `python bot.py` в подготовленном окружении.
- Передайте `BOT_TOKEN` через защищённую конфигурацию окружения. Для другого имени бота учитывайте фиксированный `BOT_USERNAME`.
- Используется polling: текущая реализация не поднимает HTTP-сервер, не слушает порт и не содержит webhook-обработчика. Выбирайте среду, поддерживающую длительную работу фонового процесса.
- Запускайте один экземпляр для одного токена: память между процессами не разделяется, несколько получателей polling могут конфликтовать.
- Обеспечьте исходящий доступ к Telegram API и корректную доставку сообщений в группе и личных чатах.
- `runtime.txt` содержит `python-3.12.9`, но поддержка этого файла зависит от платформы; при необходимости укажите версию Python в настройках среды. Конфигурация конкретного хостинга в рассмотренных файлах отсутствует.
- Перезапуски и обновления сейчас обнуляют состояние. Планируйте их с учётом текущих игр; резервировать базу в этой версии невозможно, поскольку её нет.
- Для планируемой SQLite потребуется постоянный диск и резервное копирование файла базы. Это требование будущей версии, а не часть текущего развёртывания.
