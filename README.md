# CLUJ-SANTA-BOT

Telegram-бот для «Тайного Санты» в группах. Организатор создаёт игру с бюджетом, участники регистрируются кнопкой, бот распределяет получателей и отправляет личные сообщения.

Реализованы **SS-1: управление событиями и регистрация** и **SS-2: безопасная жеребьёвка и уведомления**. Полные требования v1.1 находятся в [утверждённой спецификации](docs/functional-specification.md). Личное меню SS-3 пока не реализовано.

## Технологии и зависимости

- Python 3.12.9 (`runtime.txt`).
- `python-telegram-bot==21.6` (`requirements.txt`).
- SQLite через стандартный `sqlite3`, без отдельного сервера БД и дополнительных пакетов.
- Асинхронные обработчики Telegram, inline-кнопки, long polling, один процесс с последовательной обработкой обновлений.
- Только русский интерфейс и валюта RON. Архитектура рассчитана на сезонное использование около двух месяцев в году.

## Реализованные возможности

- Несколько независимых игр в одной группе или в разных группах, у каждой собственный ID, бюджет и участники.
- `/new` и `/new <название>` с вводом бюджета, предварительным просмотром и подтверждением. Организатор не обязан быть администратором и не становится участником автоматически.
- Отмена создания кнопкой или `/cancel`; черновики разделены по группе и организатору. Повторный `/new` предлагает продолжить черновик или отменить его и начать заново.
- Название после удаления крайних пробелов: 1–100 символов. Бюджет: от 0,01 до 100 000 RON включительно, максимум два десятичных знака, точка или запятая. Сумма хранится целым количеством бань, без округления неверного ввода.
- Регистрация через «🎁 Присоединиться» с Event ID, защитой от дублей и обновлением списка. Выход и удаление отдельного участника отсутствуют.
- «⚙️ Управление» в групповой карточке: только организатор может отменить открытую игру после отдельного подтверждения. Отменённая игра и её участники сохраняются, новые регистрации блокируются.
- SQLite сохраняет игры, их статусы, ID карточек, участников и активацию личного чата после перезапуска. Черновики создания остаются в памяти и могут исчезнуть.
- Имя бота для ссылок берётся из его Telegram-профиля; пользовательские имена и названия экранируются для HTML. Длинный список сокращается с указанием оставшегося числа участников.
- Жеребьёвка с подтверждением: только организатор, минимум два участника, повторная проверка статуса и состава. Изменение состава требует нового подтверждения; старые и повторные подтверждения отклоняются. При двух участниках они получают друг друга, самоназначения исключены, каждый получает ровно одного получателя и одного дарителя.
- Перед сохранением проверяется личный `/start` и выполняется нейтральная пробная отправка. Ошибка проверки оставляет игру открытой без назначений.
- Все назначения и завершённый статус фиксируются атомарно в SQLite до первой отправки результата. Блокировка записи и повторная проверка внутри транзакции защищают от одновременных жеребьёвок; сетевых запросов внутри транзакции нет.
- Личные уведомления содержат название игры, получателя, ссылку на профиль и бюджет. Пары не публикуются в группе и не показываются организатору; он видит только счётчики отправки.
- Для каждого назначения сохраняется `pending`, `sent` или `failed`. Ошибка Telegram не удаляет пары и не останавливает попытки отправки остальным участникам. Через «⚙️ Управление» организатор повторяет только `pending`/`failed`, без новой жеребьёвки.

## Команды и сценарии

| Команда или кнопка | Контекст | Действие |
| --- | --- | --- |
| `/start` | Личный чат | Сохраняет активацию личного чата, показывает приветствие |
| `/new` | Группа / супергруппа | Запрашивает название, затем бюджет |
| `/new <название>` | Группа / супергруппа | Проверяет название и запрашивает бюджет |
| `/cancel` | Группа / супергруппа | Отменяет собственный черновик в этой группе |
| «Создать игру» | Предварительный просмотр | Сохраняет игру и превращает сообщение просмотра в её карточку |
| «Отмена» | Создание | Удаляет черновик, не затрагивая опубликованные игры |
| «🎁 Присоединиться» | Карточка игры | Необратимо регистрирует участника в конкретной игре |
| «⚙️ Управление» | Карточка игры | Открывает действия организатора |
| «🎲 Провести жеребьёвку» | Открытая игра | Показывает состав и запрашивает подтверждение |
| «Подтвердить жеребьёвку» | Подтверждение | Повторно проверяет игру и состав, проверяет личные чаты, сохраняет пары и начинает рассылку |
| «Повторить неудачные уведомления» | Управление завершённой игрой | Повторяет `pending`/`failed` с прежними назначениями |

1. Добавьте бота в группу с правами отправки и редактирования собственных сообщений.
2. Отправьте `/new` или `/new Тайный Санта Клуж`.
3. На вопросы о названии и бюджете отвечайте **ответом на соответствующее сообщение бота**. Обычный текст группы и ответы других пользователей не изменяют черновик. Для отмены используйте кнопку или `/cancel`.
4. Проверьте название и бюджет и нажмите «Создать игру».
5. Участники нажимают «🎁 Присоединиться» и открывают ссылку на бота в карточке, чтобы отправить `/start` лично. Регистрация допустима и до активации личного чата.
6. Организатор при желании регистрируется отдельно. Для отмены игры: «⚙️ Управление» → «Отменить игру» → «Да, отменить игру».
7. После личного `/start` всех участников организатор нажимает «Провести жеребьёвку», проверяет состав и подтверждает. «Назад» оставляет игру открытой. До commit возможны пробные сообщения, но сообщения с назначениями отправляются только после сохранения всех пар.
8. После рассылки бот сообщает количество успешных, неудачных и ожидающих отправки уведомлений. Если есть ошибки или произошёл перезапуск посреди рассылки: «⚙️ Управление» → «Повторить неудачные уведомления». Получатели подарков не изменятся.

## Локальная настройка и окружение

Нужны Python 3.12.9, `pip`, токен от BotFather и доступ к Telegram API. Из корня проекта создайте окружение и установите зависимости самостоятельно.

Windows PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
$env:BOT_TOKEN = '<ТОКЕН_ВАШЕГО_БОТА>'
$env:DATABASE_PATH = './data/santa.sqlite3'
```

Linux/macOS:

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
export BOT_TOKEN='<ТОКЕН_ВАШЕГО_БОТА>'
export DATABASE_PATH='./data/santa.sqlite3'
```

`BOT_TOKEN` обязателен и читается при запуске. Не публикуйте его в Git, сообщениях и логах. Все значения токена в документации — заполнители. `.env.example` показывает имена переменных; **`.env` автоматически не загружается**, переменные нужно передать через оболочку или платформу размещения.

`DATABASE_PATH` необязателен: по умолчанию используется `data/santa.sqlite3` относительно каталога `bot.py`. Явно заданный относительный путь разрешается относительно рабочего каталога процесса; для размещения предпочтителен абсолютный путь на постоянном диске. Родительские каталоги и таблицы создаются автоматически, существующие записи не удаляются. У процесса должны быть права записи в каталог БД.

`.gitignore` исключает `.env`, `.venv`, Python-кэш, локальные `*.db`, `*.sqlite`, `*.sqlite3` и их служебные файлы.

## Запуск локально

После настройки окружения:

```powershell
.\.venv\Scripts\python.exe bot.py
```

Linux/macOS:

```bash
.venv/bin/python bot.py
```

Остановка — `Ctrl+C`. Без `BOT_TOKEN` запуск завершается с `RuntimeError: BOT_TOKEN не найден`. Импорт модулей и выполнение тестов не запускают polling и не создают рабочую БД.

## Автоматизированные проверки

Хранение, валидация и алгоритм жеребьёвки проверяются стандартным `unittest` без Telegram-токена и сети; базы тестов создаются во временных каталогах. Проверки обработчиков используют имитацию Telegram и требуют уже установленной зависимости из `requirements.txt`. Есть проверки двух участников, однозначности пар, подтверждения, повторных запусков, конкурирующих SQLite-подключений, отката транзакции, перезапуска, ошибок доставки и повтора без изменения назначений.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Linux/macOS:

```bash
.venv/bin/python -m unittest discover -s tests -v
```

Если `python-telegram-bot` отсутствует, модуль проверок обработчиков пропускается; проверки хранения и валидации выполняются независимо.

## Текущие ограничения и оставшиеся этапы

**SS-2 реализован; ограничения доставки:**

- `sent` означает, что Telegram подтвердил отправку, а не прочтение. Даже успешная предварительная проверка не гарантирует последующую доставку.
- После сбоя между отправкой и записью `sent` допустим повтор сообщения с **тем же** назначением. Гарантия ровно одного уведомления не предоставляется.
- Повтор рассылки запускается вручную организатором. Автоматического фонового планировщика нет. После перезапуска `pending` и `failed` остаются доступны в управлении игрой.
- Подтверждения жеребьёвки хранятся в памяти. После перезапуска до commit нужно запросить новое подтверждение; после commit пары уже сохранены и не меняются.
- Завершённые игры старой версии SS-1 без сохранённых пар не перерисовываются: восстановить их результаты из БД нельзя, повторная жеребьёвка запрещена. Новая таблица назначений добавляется при запуске без удаления существующих игр.
- Пока SS-3 отсутствует, повторного просмотра пары через меню нет; доступны исходное личное сообщение и повтор неудачной отправки организатором.
- При длительной рассылке один polling-процесс обрабатывает другие обновления после её завершения. Для небольшой сезонной нагрузки отдельная очередь не требуется; при ограничении частоты Telegram используется ручной повтор позднее.

**SS-3:** меню «Мои игры» → карточка → «Кому я дарю?», команды `/mygames` и `/help`, проверка доступа только к собственной паре. Пока `/start` показывает только приветствие.

**Ограничения SS-1:** черновики пропадают при перезапуске; удалённая карточка или потеря прав бота мешают обновлению сообщения, но не удаляют SQLite-записи. При ошибке обновления можно повторить нажатие. Если сбой произошёл после сохранения игры до обновления предварительного просмотра, повтор «Создать игру» восстанавливает карточку, включая после перезапуска, без новой игры. Кнопки старой версии без Event ID отклоняются; прежнее состояние из памяти автоматически не переносится. При большом списке участников карточка показывает только его начало и общее количество.

## Развёртывание

- Один постоянно работающий polling-процесс в период игр, без HTTP-сервера и webhook. Отдельный сервер БД и очередь задач не нужны.
- Передавайте токен через защищённые переменные окружения и обеспечьте исходящий доступ к Telegram.
- **SQLite должна находиться на постоянном диске.** Обновление приложения не должно удалять БД; сохраняйте один и тот же `DATABASE_PATH` при перезапусках.
- Для резервного копирования используйте SQLite backup API либо копируйте базу при остановленном процессе; проверяйте восстановление. Не размещайте резервные копии с данными участников в Git.
- `runtime.txt` указывает Python 3.12.9; его поддержка зависит от платформы. Хостинг пока не выбран.
- После сезона процесс можно остановить с сохранением БД. Пока он выключен, команды и уведомления недоступны.
- Автоматизированные проверки покрывают сохранение пар, откат, конкурирующие подключения, ошибки и повторы рассылки. Проверка выбранного хостинга, резервных копий и эксплуатации остаётся частью SS-4.
